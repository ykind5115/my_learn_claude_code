如果你看到的是一个神秘咒语——不知道它怎么工作的，只知道"这样写就行"——那你永远无法真正理解 Linux，也无法理解 Agent 在 Linux 上做了什么。

## 核心模型：进程工厂

想象一个自动化工厂。你（用户）是**工厂老板**。工厂里的一切都围绕一个核心概念运转：**进程**。

```
┌─────────────────────────────────────────────────────────┐
│                    进程工厂 (Linux)                      │
│                                                         │
│   ┌─────────────┐        ┌─────────────────────┐       │
│   │  调度办公室  │───────→│      工人们(进程)     │       │
│   │   (Shell)   │  派活   │                     │       │
│   └─────────────┘        │  PID 1001: ls       │       │
│                          │  PID 1002: grep     │       │
│   ┌─────────────┐        │  PID 1003: python   │       │
│   │   公告板     │        └────────┬────────────┘       │
│   │ (环境变量)   │                 │                    │
│   └─────────────┘        ┌────────┴────────────┐       │
│                          │    传送带(管道/IO)    │       │
│   ┌─────────────┐        │  stdin→[工人]→stdout │       │
│   │   仓库       │        │         ↘stderr     │       │
│   │  (文件系统)   │        └─────────────────────┘       │
│   └─────────────┘                                       │
│                                                         │
│   ┌─────────────┐        ┌─────────────────────┐       │
│   │   对讲系统    │        │   安全徽章(权限)      │       │
│   │   (信号)     │        │   rwx / root / sudo  │       │
│   └─────────────┘        └─────────────────────┘       │
└─────────────────────────────────────────────────────────┘
```

## 核心角色对照表

| 概念 | 工厂比喻 | 一句话理解 |
|------|---------|-----------|
| **进程** | 工人 | 真正干活的人，每个有工号(PID) |
| **Shell** | 调度办公室 | 你在这里下达指令，shell 分配工人去执行 |
| **stdin** | 进料口 | 工人从哪拿原材料（键盘/文件/上游管道） |
| **stdout** | 出货口 | 成品从哪出去（屏幕/文件/下游管道） |
| **stderr** | 废料口 | 错误信息单独排出（也到屏幕，但独立于 stdout） |
| **管道 `\|`** | 传送带 | 工人 A 的出货口直接连到工人 B 的进料口 |
| **文件** | 原料/成品 | 存在仓库(磁盘)里的东西 |
| **文件系统** | 仓库货架 | /bin 是工具间，/etc 是配置柜，/home 是私人储物柜 |
| **权限 (rwx)** | 安全徽章 | 谁能进哪个区域、能读还是能改 |
| **信号** | 对讲广播 | "全体注意：停止工作"(SIGTERM)、"着火了快跑"(SIGKILL) |
| **环境变量** | 公告板 | 全局配置，每个工人抬头就能看到 |
| **root** | 工厂总管 | 有所有区域的钥匙，可以做任何事 |
| **sudo** | 临时授权 | "总管的钥匙借我用一下" |

## 三个关键哲学

### 1. Everything is a file（一切都是文件）

Linux 最大的设计哲学。普通文件、目录、进程信息、硬件设备、网络连接——在 Linux 眼里都是"文件"。

```bash
# 普通文件
cat /home/user/readme.txt

# 进程信息也是"文件"！
cat /proc/12345/status      # 读取进程 12345 的状态

# 硬件设备也是"文件"
cat /dev/sda                 # 读取整个硬盘的内容（需要 root）

# 甚至当前进程的内存也是"文件"
cat /proc/self/maps          # 看自己的内存布局
```

理解了这一点，你就理解了为什么 Agent 的 `read_file` 工具能读 `/proc` 里的进程信息。

### 2. Small programs that do one thing well（小而专的工具）

Linux 的命令行工具每个只做一件事，但做到极致。`ls` 只列文件，`grep` 只搜文本，`wc` 只计数。组合起来威力无穷：

```bash
# 统计当前目录下有多少 Python 文件
ls *.py | wc -l

# ls 只管列出文件 → 管道传过去 → wc 只管计数
```

### 3. Everything is text（一切皆文本）

配置文件是文本，进程信息是文本，命令输出也是文本。这让管道的威力最大化——因为所有工具都说同一种"语言"。
