## 问题 — 你启动了一个 Python 脚本，卡住了

Ctrl+C 停了它，但你不知道它之前在干什么。你想：
1. 看看现在有哪些进程在跑
2. 找到那个卡住的，看看它占了多少内存
3. 优雅地让它退出（或暴力杀掉）
4. 下次让它在后台跑，别占着终端

---

## 原理：进程的一生

```
fork()                    exec()              exit()
  │  父进程克隆自己            │  变成新程序        │  进程结束
  ▼                          ▼                   ▼
[Born] ──────→ [Ready] ──────→ [Running] ──────→ [Zombie]
                 ▲  │                          (等待父进程收尸)
                 │  │  时间片到
                 └──┘
              [Sleeping] (等待 I/O)
              [Stopped]  (被 Ctrl+Z 暂停)
```

## 核心概念

### 查看进程

| 命令 | 用途 |
|------|------|
| `ps` | 当前终端的进程快照 |
| `ps aux` | 所有用户的所有进程 |
| `top` / `htop` | 实时进程面板（q 退出） |
| `pstree` | 进程树（父子关系一目了然） |

### 前台 vs 后台

```bash
python train.py &       # & 让进程在后台跑
jobs                    # 查看后台任务
fg %1                   # 把后台任务 1 拉回前台
bg %1                   # 让暂停的任务 1 在后台继续
```

### 信号 — 对讲广播

| 信号 | 编号 | 含义 | 能捕获吗 |
|------|------|------|---------|
| SIGINT | 2 | Ctrl+C，"请你自己停下来" | ✅ |
| SIGTERM | 15 | "请优雅退出" | ✅ |
| SIGKILL | 9 | "立刻死！" | ❌ |
| SIGSTOP | 19 | "暂停" | ❌ |

`s01` 的 `subprocess.run(timeout=5)`——超时就发 SIGTERM，还不死就发 SIGKILL。

### 僵尸进程

子进程死了，父进程没来得及 `waitpid()` 收尸 → 子进程变成僵尸（Z 状态）。不占 CPU 和内存，但占着 PID 槽位。

## 小结

```
ps aux        查看所有进程
top           实时进程面板
&             后台运行
Ctrl+C        SIGINT (可捕获的"请停下")
kill -9       SIGKILL (不可捕获的"立刻死")
僵尸进程      子进程死了父进程没收尸
```
