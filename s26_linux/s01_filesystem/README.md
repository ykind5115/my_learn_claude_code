# s26-01: 文件系统层次结构

[← 返回概览](../README.md) | [下一章：文件操作与权限](../s02_file_ops/)

> *"文件都在哪？/bin、/etc、/var、/tmp 是干什么的？"*

---

## 问题 — 你敲 `ls /` 看到了什么？

```
bin  boot  dev  etc  home  lib  mnt  opt  proc  root  run  sbin  tmp  usr  var
```

这些不是随便起的名——Linux 有一个标准叫 **FHS（Filesystem Hierarchy Standard，文件系统层次结构标准）**。每个目录有明确的用途。

---

## 原理：仓库的分区图

把文件系统想象成工厂仓库的**分区规划**：

| 目录 | 工厂比喻 | 里面有什么 |
|------|---------|-----------|
| `/bin` | 工具间 | 最基础的工具：`ls`、`cat`、`cp`、`bash` |
| `/etc` | 配置柜 | 系统配置文件（"etc" = "et cetera"，杂项） |
| `/home` | 私人储物柜 | 每个用户的私有文件都在 `/home/用户名/` |
| `/var` | 动态存放区 | 日志、缓存、数据库——经常变化的数据 |
| `/tmp` | 临时堆放区 | 所有人都能写，重启就清空 |
| `/proc` | 工人花名册 | 虚拟文件系统：每个进程的状态都是"文件" |
| `/dev` | 设备间 | 硬件设备以文件形式存在（`/dev/sda` = 硬盘） |
| `/usr` | 用户程序区 | 用户安装的软件、库文件 |
| `/opt` | 外来软件区 | 第三方大型软件（Google Chrome、VMware） |
| `/boot` | 启动区 | 启动系统必需的文件（内核、引导程序） |
| `/root` | 总管办公室 | root 用户的家目录（不在 /home 里） |

---

## 核心概念

### `/proc` — 窥探内核的窗口

`/proc` 是一个**假的文件系统**——里面的文件不存在于磁盘上，而是内核实时生成的。

```bash
cat /proc/cpuinfo        # CPU 信息（几核、多快）
cat /proc/meminfo         # 内存信息（总共多少、用了多少）
cat /proc/12345/status    # 进程 12345 的状态
cat /proc/12345/fd/       # 进程 12345 打开了哪些文件
```

这就是"Everything is a file"的最佳体现——连进程的运行状态都是"文件"。

### 绝对路径 vs 相对路径

```
/home/user/project/code.py    ← 绝对路径（从 / 出发）
./code.py                     ← 相对路径（从当前目录出发）
../s01/code.py                ← 相对路径（先退到父目录再进去）
```

## 小结

```
/ (根目录) = 仓库入口
├── /bin     工具间（基础命令）
├── /etc     配置柜（系统配置）
├── /home    私人储物柜（你的文件）
├── /var     动态存放区（日志、缓存）
├── /tmp     临时堆放区（重启清空）
├── /proc    工人花名册（进程信息）
└── /dev     设备间（硬件即文件）
```
