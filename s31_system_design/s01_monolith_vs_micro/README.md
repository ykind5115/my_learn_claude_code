# s31-01: 单体 vs 微服务

[← 返回概览](../README.md) | [下一章：负载均衡](../s02_load_balancer/)

> *"什么时候把大应用拆成小服务？什么时候不该拆？"*

---

## 单体 (Monolith)

```
┌──────────────────────────┐
│      一个进程跑所有功能     │
│   auth + api + db + tasks │
└──────────────────────────┘
优点: 简单、调试方便、部署容易
缺点: 改一处要部署整个应用、无法独立扩缩容
```

## 微服务 (Microservices)

```
┌────┐ ┌────┐ ┌────┐
│auth│ │api │ │task│
└────┘ └────┘ └────┘
  各自独立部署、独立扩缩容
优点: 独立扩缩容、技术栈灵活
缺点: 运维复杂、网络开销、数据一致性难
```

**原则**：先单体，真正痛了再拆。不要为了"微服务"而微服务。
