## 为什么大多数数据结构教程让人学不会？

传统教程：

```
第 1 章: 数组 —— 连续内存，O(1) 访问
第 2 章: 链表 —— 离散内存，O(n) 访问，O(1) 插入
第 3 章: 栈   —— LIFO，push/pop
...
```

你记住了定义，但脑子里没有画面。你不知道**什么时候该用哪个**。遇到真实问题，你第一反应不是「这里应该用跳表」，而是「这道题用数组能做吗」。

**本课程反其道而行之**：每章从一个真实的工程问题出发：

- 「怎么管理代码的历史版本？」→ 链表 → DAG → Mini Git
- 「浏览器的前进后退怎么实现？」→ 栈 → Mini Browser
- 「Redis 为什么这么快？」→ 哈希表 → Mini Redis
- 「游戏排行榜怎么做？」→ 跳表 → Mini Leaderboard
- 「数据库为什么用 B+ 树？」→ B+ 树 → Mini DB Index

**工程问题 → 数据结构 → Python 实现 → Mini 项目。** 学完你不仅知道「有什么数据结构」，还知道「什么时候该用哪个」。

## 开始之前：你需要什么基础？

- Python 基础：类、函数、`__iter__`、列表/字典的基本使用
- 理解时间复杂度（知道 O(1)、O(n)、O(log n) 是什么意思即可）
- 会用终端运行 Python 脚本

> 不需要学过任何数据结构课程。不需要刷过 LeetCode。

## 如何使用本课程

### 每章的学习节奏

1. **读「本章工程问题」** — 理解这个数据结构要解决什么实际问题
2. **读「为什么普通方法不够好」** — 理解这个数据结构的「存在理由」
3. **读数据结构原理** — 理解核心思想，看图
4. **运行 code.py** — 看数据结构在操作中的可视化过程
5. **读实现源码** — 逐行理解 Python 实现
6. **看项目框架** — 理解「这个数据结构怎样成为一个系统的骨架」
7. **做思考题** — 测试自己是否真正理解了

### 不要跳章

每章的数据结构是下一章的基础。s06 依赖 s05 的哈希表，s07 依赖 s06 的痛点理解，s08 依赖 s07 的跳表。

### 每章的文件结构

```
sXX_chapter_name/
├── README.md           # 完整教学（10 节）
├── <data_structure>.py # 数据结构从零实现
├── mini_<app>.py       # Mini 应用框架（接口 + 骨架，你来填充）
└── code.py             # 主入口（运行演示）
```

- **`<data_structure>.py`**：数据结构的完整 Python 实现。读完原理后直接看源码。
- **`mini_<app>.py`**：把这个数据结构用在一个真实系统里的模板。接口已定义好，关键算法留给你实现。
- **`code.py`**：运行 `python s24_data_structures/sXX_xxx/code.py` 可以看到数据结构的可视化操作过程。
