# s06: 有序 vs 无序 — ★ 哈希表为什么不够？

> *"O(1) 不是免费的。哈希表让你瞬间存取，但偷走了 key 之间的顺序。当你需要排序、排名、范围查询时，你得另想办法。"*
>
> **前提知识**: 学过 s05（哈希表）。理解 O(1) vs O(n) vs O(log n)。

---

## 1. 本章工程问题

你做完 s05 的 Mini Redis，觉得哈希表真香——O(1) 存取，简单好用。

现在你接到一个新需求：**游戏排行榜**。

```
需求:
  1. 百万玩家，随时有人分数变化 → 更新分数
  2. 随时查「某人的排名」→ 第几名
  3. 随时查「Top 100」→ 最高分的 100 人
  4. 「分数在 2000~2500 之间的玩家」→ 范围查询
```

你打开 Mini Redis，开始写……然后发现：

```python
# 用哈希表实现排行榜？
ht.put("Alice", 2500)
ht.put("Bob", 2200)
ht.put("Charlie", 1800)

# 需求 1: 更新分数 → O(1) ✅ 哈希表可以
ht.put("Alice", 2600)

# 需求 2: Alice 排第几名？
# 哈希表: 我不知道！key 之间没有顺序关系！

# 需求 3: Top 100？
# 哈希表: 我只能把所有 key 取出来，排序: O(n log n)
# 每 5 秒刷一次排行榜 → 百万数据 × O(n log n) = 疯了

# 需求 4: 分数在 2000~2500？
# 哈希表: 我必须遍历所有 key: O(n)
```

**哈希表给了你 O(1) 的存取，但完全放弃了「顺序」。** 本章是过渡章——让你深刻理解这个 tradeoff，然后 s07 用跳表来解决。

## 2. 有序 vs 无序：一张对比表

| 需求 | 哈希表（无序） | 有序数组 |
|------|--------------|---------|
| 按 key 查 value | **O(1)** ✅ | O(log n) |
| 插入/更新 | **O(1)** ✅ | O(n) ❌ |
| 范围查询（80~90 分） | O(n) ❌ | **O(log n + k)** ✅ |
| 排名（Alice 排第几） | O(n log n) ❌ | **O(1)** ✅ |
| Top N | O(n log n) ❌ | **O(1)** ✅ |
| 按顺序遍历所有 | O(n log n) ❌ | **O(n)** ✅ |

> 一半的操作哈希表是满分（O(1)），另一半是零分（完全做不到或 O(n log n)）。有序数组刚好反过来。

## 3. 两种方案尝试解决排行榜

### 方案 A：哈希表（s05 的 HashTable）

```python
scores = HashTable()
scores.put("Alice", 2500)
scores.put("Bob", 2200)
# ...

# Top 10 怎么做？
all_scores = [(k, scores.get(k)) for k in scores.keys()]  # O(n)
all_scores.sort(key=lambda x: x[1], reverse=True)          # O(n log n)
top10 = all_scores[:10]                                    # O(1)
```

**问题**：每次查 Top 10 都要全量排序——100 万条数据 × O(n log n) ≈ 2000 万次比较。每 5 秒刷新一次？系统直接崩溃。

### 方案 B：有序数组

```python
class OrderedArray:
    def __init__(self):
        self._data = []  # 始终保持有序

    def insert(self, item):
        # 二分找到插入位置 → O(log n)
        # list.insert() 移动元素 → O(n)
        ...
    
    def top_n(self, n):
        return self._data[-n:]  # 数组已经有序 → O(1)！
```

**优势**：Top N 和范围查询飞快——因为数据始终有序。
**代价**：插入变成 O(n)——每次新分数进来，要移动所有比它大的元素。百万玩家 = 每次更新移动几十万元素。

## 4. 有序数组 + 二分查找工作原理

### 二分查找

```
在 [2, 5, 8, 12, 16, 23, 38, 56, 72, 91] 中找 23:

第 1 步: 看中间 (16)
  [2,5,8,12,16, 23,38,56,72,91]
              ↑
             16 < 23 → 在右半边找

第 2 步: 看右半边的中间 (56)
  [23,38,56,72,91]
          ↑
         56 > 23 → 在左半边找

第 3 步: 
  [23,38]
     ↑
    23 = 23 → 找到！

10 个元素 → 最多 4 次比较
100 万元素 → 最多 20 次比较
```

### 插入的代价

```
在 [2,5,8,12,16,38,56,72,91] 中插入 23:

[2,5,8,12,16, ???, 38,56,72,91]
               ↑
             23 应该在这里 → 从 38 开始全部往后移一位
             
[2,5,8,12,16, 23, 38,56,72,91]
              ↑   ~~~~~~~~~~~ O(n) 移动
```

## 5. Python 实现

打开 `ordered_array.py`，核心代码：

```python
def binary_search(arr, target):
    """二分查找 — O(log n)"""
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

class OrderedArray:
    def insert(self, item):
        """插入并保持有序 — O(n)（移动元素）"""
        key = self.key_func(item)
        # 二分查找找到插入位置 — O(log n)
        left, right = 0, len(self._data)
        while left < right:
            mid = (left + right) // 2
            if self.key_func(self._data[mid]) < key:
                left = mid + 1
            else:
                right = mid
        self._data.insert(left, item)  # ← O(n)！这才是瓶颈

    def range_query(self, lo, hi):
        """范围查询 — O(log n + k)"""
        # 二分找到起点 — O(log n)
        # 顺序遍历直到超过 hi — O(k)
        ...

    def top_n(self, n):
        """Top N — O(1)（数组已经有序）"""
        return self._data[-n:]
```

## 6. 时间复杂度分析

### 排行榜场景下的对比

假设 100 万玩家，每秒 1000 次操作（900 次查排名 + 100 次更新分数）：

| 方案 | 更新分数 | 查 Top 100 | 每秒总耗时 |
|------|---------|-----------|-----------|
| 哈希表 | O(1) ≈ 0μs | O(n log n) ≈ 200ms | 900 × 200ms = 180s ❌ |
| 有序数组 | O(n) ≈ 1ms | O(1) ≈ 0μs | 100 × 1ms = 0.1s ✅ |

> 哈希表在「高频查询排序/排名」的场景下完全不可用。有序数组可以——但插入慢。有没有**两全其美**的方案？

## 7. 桥梁作用：引出跳表

通过本章，你清楚地看到了两条路：

```
哈希表路线:
  O(1) 插入, O(1) 查找 → 但无法排序/排名
  → 适合: 缓存, key-value 存储, 去重

有序数组路线:
  O(log n) 查找, O(1) 排序/排名 → 但插入 O(n)
  → 适合: 静态数据, 很少更新的排行榜

我们想要:
  O(log n) 插入 + O(log n) 查找 + 能排序 + 能排名
  → ??? 
```

**s07 的跳表（Skip List）就是答案。**

## 10. 本章总结

| 概念 | 一句话 |
|------|--------|
| 无序 vs 有序 | 哈希表放弃顺序换速度；有序数组放弃速度换顺序 |
| 范围查询 | 哈希表 O(n)，有序数组 O(log n + k) |
| 排名查询 | 哈希表做不到，有序数组 O(1) |
| 二分查找 | 每次排除一半——O(log n) |
| 插入代价 | 有序数组 O(n)——所有更大的元素都要移动 |
| 核心矛盾 | 需要「插入快 + 能排序」→ 跳表来解决 |

> **核心收获**：数据结构的选择不是「谁更好」，而是「我要放弃什么」。哈希表放弃顺序换 O(1)；有序数组放弃插入速度换排序能力。下一章的跳表，试图在这两者之间找到平衡点。
