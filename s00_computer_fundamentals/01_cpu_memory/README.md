# s00-01: CPU、内存、缓存

[← 返回概览](../README.md) | [下一章：存储](../02_storage/)

> *CPU 执行指令，内存暂存数据，缓存弥合两者之间的速度鸿沟。理解这个金字塔，你就理解了计算机为什么是现在这样设计的。*

---

## 问题 — 为什么 CPU 不能直接从磁盘读数据？

CPU 每秒执行 30 亿条指令。磁盘寻道一次 10 毫秒。

**10ms × 30 亿/s = 3000 万条指令被浪费在一次磁盘读取里。**

所以计算机设计了一个存储层级——越靠近 CPU 越快、越贵、越小。

---

## 原理：存储金字塔

```
         ┌──────────────┐
         │   寄存器      │  ~0.3ns │ 几百字节   │ CPU 内部
         ├──────────────┤
         │  L1 缓存      │  ~1ns   │ 64KB       │ 每核独有
         ├──────────────┤
         │  L2 缓存      │  ~5ns   │ 256KB-1MB  │ 每核独有
         ├──────────────┤
         │  L3 缓存      │  ~15ns  │ 4-32MB     │ 所有核共享
         ├──────────────┤
         │   内存(RAM)   │ ~100ns  │ 8-64GB     │ CPU 外
         ├──────────────┤
         │   SSD 磁盘    │ ~100µs  │ 256GB-4TB  │ 持久化
         ├──────────────┤
         │   HDD 磁盘    │ ~10ms   │ 1-8TB      │ 持久化(慢)
         └──────────────┘
```

## 核心概念

### 1. CPU — 只做四件事

```
取指(Fetch) → 译码(Decode) → 执行(Execute) → 写回(Write-back)
     ↑                                              │
     └──────────────────────────────────────────────┘
```

CPU 不"理解"代码——它只是机械地取指令、执行、取下一条。Python 的 `while True` 最终被编译成几十条机器指令，CPU 一条条跑。

**寄存器**：CPU 内部最快的存储。`a = b + c` 这行代码——b 和 c 的值先加载到寄存器，ALU（算术逻辑单元）算出结果，再存回寄存器或内存。整个过程不到 1 纳秒。

**多核**：现代 CPU 有多个物理核心。4 核 CPU = 4 个工人可以同时干活。Python 多进程可以利用多核；多线程因为 GIL 不行。

### 2. 内存 — 工作台

```python
a = [1, 2, 3]     # 列表对象分配在堆上
b = a             # b 指向同一个对象！不是复制
```

内存分为几个区域：
- **代码段**：程序的机器指令
- **数据段**：全局变量
- **堆**：`malloc`/`new` 分配的对象（Python 的对象都在堆上）
- **栈**：函数调用的局部变量（LIFO，后进先出）

`id(a)` 返回 Python 对象的内存地址（CPython 中是真实地址）。

### 3. 缓存 — 局部性原理

为什么缓存有效？两个规律：

- **时间局部性**：刚访问的数据很可能马上再访问（循环里的变量）
- **空间局部性**：访问了地址 X，大概率也会访问 X+1（数组遍历）

```python
# 空间局部性的例子：数组顺序访问
for i in range(1000000):
    total += arr[i]    # arr[i] 和 arr[i+1] 在内存里相邻
                       # CPU 预取整块数据到缓存，大幅加速
```

Python 的 `functools.lru_cache` 就是手动版的缓存——记住函数的结果，同样参数直接返回缓存值。

### 4. 这跟 Agent 有什么关系？

- Anthropic API 的 **prompt caching**：重复的 system prompt 不需要每次传，引用缓存 ID。省钱 + 加速（和 CPU 缓存的逻辑一模一样）
- `.pyc` 字节码缓存、pip 包缓存、Docker 层缓存——全是缓存思想
- 模型推理时，KV Cache 存注意力计算结果，避免重复计算

## 小结

```
存储层级: 寄存器 → L1/L2/L3 → 内存 → 磁盘
          越快越贵越小          越慢越便宜越大

局部性原理: 时间局部性(刚用过的还会用)
           空间局部性(相邻的也会用)

缓存思想: 记下结果，下次直接用
         → Prompt Caching, .pyc, LRU Cache 都是这个
```
