# s00-06: 协程

[← 返回概览](../README.md) | [上一章：线程](../05_thread/) | [下一章：CPU/内存/缓存](../01_cpu_memory/)

> *协程是用户态的"轻量级线程"。你用 `await` 主动让出控制权，运行时在 I/O 等待期间切换到其他协程。没有 GIL 问题，因为本质上还是单线程。*

---

## 问题 — 有了线程为什么还要协程？

线程由 OS 内核调度——创建、切换、销毁都有开销。当你想同时处理 1000 个网络请求时：

- **1000 个线程**：每个线程 ~1MB 栈空间 = 1GB 内存 + 频繁的 OS 上下文切换
- **1000 个协程**：每个协程 ~KB 级内存 + 在用户态切换（不经过内核）

协程 = **高并发 I/O 的最优解**。

---

## 原理

```
单线程 + 事件循环

  await fetch(A) ──→ 发起请求 ──→ 等待网络 ──┐
  await fetch(B) ──→ 发起请求 ──→ 等待网络 ──┤  事件循环在这三个
  await fetch(C) ──→ 发起请求 ──→ 等待网络 ──┘  之间来回切换
                                            │
  A 返回了！←────────────────────────────────┘
  │
  处理 A 的结果
  │
  B 返回了！→ 处理 B 的结果
```

你看到的是 `await`，它背后是**事件循环**在管理所有协程的状态。

---

## 核心概念

### 1. 协作式 vs 抢占式

- **线程**（抢占式）：OS 随时暂停你，"时间片到了"。你控制不了
- **协程**（协作式）：你自己 `await` 时才让出。不 `await` 就一直跑

### 2. async / await 语法

```python
async def fetch(url):        # async def = 这是一个协程函数
    data = await http_get(url)  # await = "这里要等，你先忙别的"
    return data
```

- `async def` 定义的函数返回一个**协程对象**，不是直接执行
- `await` 只能在 `async def` 内部使用
- `await` 后面跟的是"可等待对象"（协程、Task、Future）

### 3. 事件循环

```python
import asyncio

async def main():
    # gather 并发运行多个协程
    results = await asyncio.gather(
        fetch("A"),
        fetch("B"),
        fetch("C"),
    )

asyncio.run(main())  # 创建事件循环，运行 main()
```

`asyncio.gather()` = "这几个一起跑，全部完成后再继续"。

### 4. 什么时候用协程 vs 线程 vs 进程？

| 场景 | 选择 | 理由 |
|------|------|------|
| 大量并发 I/O（API 调用、爬虫） | **协程** | 最轻量，单线程无锁 |
| CPU 密集计算 | **多进程** | 绕过 GIL |
| 调用阻塞的 C 库 | **线程** | 阻塞操作会卡住事件循环 |
| 需要强隔离 | **多进程** | 独立地址空间 |

### 5. 协程的陷阱

```python
# ❌ 在协程里调用阻塞函数——整个事件循环卡住
async def bad():
    time.sleep(5)  # 阻塞！协程全停

# ✅ 用异步版本
async def good():
    await asyncio.sleep(5)  # 不阻塞，让出控制权
```

## 小结

```
协程: async def + await + 事件循环
      ↓
协作式: 自己 await 时才让出（不是被 OS 抢走）
      ↓
asyncio.gather: 并发运行，全部完成再继续
      ↓
适用: 大量 I/O 并发（网络请求、文件操作）
不适用: CPU 密集（阻塞操作会卡事件循环）
```
