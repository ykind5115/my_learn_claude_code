# s00-05: 线程

[← 返回概览](../README.md) | [上一章：进程](../04_process/) | [下一章：协程](../06_coroutine/)

> *线程是进程内部的"执行流"。一个进程可以有多个线程，共享同一块内存，但 Python 的 GIL 限制了它们并行计算的能力。*

---

## 问题 — 为什么需要线程？

进程是隔离开的——进程 A 不能直接读写进程 B 的内存。但有时候你需要**共享数据的同时并发执行**：

- s13 BackgroundTasks：Agent 要在后台记录日志，同时继续处理用户输入
- s02 并行工具：模型一次返回多个 tool_use 块，要同时执行
- s15 Agent 团队：多个 Agent 共享消息总线

这些场景用进程太重（创建开销大、通信麻烦），用协程不够（有些操作是阻塞的）。线程是中间的甜点位。

---

## 原理

```
进程
├── 主线程 (程序入口，一直存在)
├── 线程 A (后台写日志)
├── 线程 B (处理网络请求)
└── 线程 C (定时清理缓存)
        │
        └── 共享: 所有全局变量、堆内存
            独立: 各自的栈、寄存器、程序计数器
```

---

## 核心概念

### 1. 线程 vs 进程

| | 线程 | 进程 |
|---|---|---|
| 共享内存 | ✅ 同一进程的线程共享 | ❌ 隔离 |
| 创建开销 | ~微秒 | ~毫秒（fork + 新地址空间） |
| 通信 | 直接读写共享变量 | 管道 / Socket / 共享内存 |
| 一个崩了 | 可能拖垮整个进程 | 只影响自己 |
| Python 特殊限制 | GIL | 无 |

### 2. Python 的 GIL（全局解释器锁）

CPython 有一个大锁——**同一时刻只有一个线程能执行 Python 字节码**。

这意味着 Python 多线程**不能利用多核做并行计算**。但 I/O 操作（读文件、网络请求、`time.sleep`）会释放 GIL，让其他线程跑。

结论：**Python 多线程适合 I/O 密集型，不适合 CPU 密集型。**

### 3. 竞态条件

```python
count = 0

def increment():
    global count
    count += 1  # 不是原子操作！
    # 实际上是: tmp = count; tmp += 1; count = tmp
    # 如果两个线程同时执行，可能都读到相同的 count，
    # 导致 count 只加了 1 而不是 2
```

解决方案：**锁（Lock）**

```python
lock = threading.Lock()

def increment():
    with lock:       # 获取锁
        count += 1   # 此时只有我能执行这段代码
                      # 自动释放锁
```

### 4. 守护线程（Daemon Thread）

```python
t = threading.Thread(target=worker, daemon=True)
```

守护线程 = 主线程退出时自动被杀。s13 的后台任务通常用守护线程——Agent 退出，后台任务也跟着退出，不会阻止程序结束。

## 小结

```
线程: 共享内存、轻量、适合 I/O 并发
       ↓
Python GIL: 同一时刻只跑一个线程的 Python 代码
       ↓
竞态条件: count += 1 不是原子操作 → 加锁
       ↓
守护线程: 主线程退出时自动结束
```
