---

## 问题 — 为什么同样的代码结构反复出现？

你看了几个开源项目后会发现：配置管理总是"全局只有一个"、创建对象的代码总是"根据参数返回不同类型"、中间件总是"一层一层传下去"。

这不是巧合。这是**设计模式**——经过验证的、解决特定问题的代码结构。

---

## 什么是设计模式？

```
问题 (Problem)         →  方案 (Solution)       →  名字 (Name)
────────────────────────────────────────────────────────────
"怎么保证全局只有一个？"  →  私有构造函数 + 静态实例  →  Singleton
"怎么按参数创建对象？"    →  工厂类/方法分发创建       →  Factory
"怎么运行时切换算法？"    →  策略接口 + 具体策略类     →  Strategy
"怎么通知多个对象？"      →  订阅-发布机制             →  Observer
```

---

## 为什么学模式不靠背？

背 23 种模式的名字没用。真正有用的是：

1. **看到问题 → 想起模式**：这是"创建不同对象"的问题 → Factory
2. **看到代码 → 认出模式**：这个 `classmethod` 返回不同子类 → Factory Method
3. **看 Agent 源码 → 理解设计意图**：`@tool` 装饰器 → Decorator 模式
