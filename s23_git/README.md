# s23: Git 版本控制 — 把代码放进时间树

[中文](README.md)

> *"Git 不是一堆命令。Git 是一棵会不断长出新树枝的时间树。"*
>
> 本课程面向 **Git 零基础**的学习者。不假设你用过任何版本控制工具。
> 每一章只比上一章多一个概念，每一步都用「时间树」模型来解释「为什么」。
> 最终目标是：学完能用 Git 管理自己的项目，能参与团队协作，而且**真正理解每个命令在做什么**。

---

## 为什么大多数 Git 教程让人学不会？

传统的 Git 教学是这样：

```
第 1 课: git init, git add, git commit ← 你在背命令
第 2 课: git branch, git merge          ← 你还在背命令
第 3 课: git push, git pull             ← 你继续背命令
...
```

结果：背了 20 个命令，但一遇到冲突就慌、一看到 detached HEAD 就懵、一听说 rebase 就怕。

**本课程反其道而行之**：先用 s00 帮你建立一张「地图」——Git 的时间树模型。这张图一旦刻在你脑子里，后面所有命令都会变得自然：

- `git commit` = 在树上种一个新节点
- `git branch` = 给节点贴一张可移动的标签
- `git merge` = 两条树枝汇合在一起
- `git rebase` = 把树枝「嫁接」到另一个位置
- `git reset` = 把标签移到另一个节点上

## 开始之前：你需要什么基础？

- 会用终端（命令行）——会 `cd`、`ls`、`mkdir` 就行
- 会用文本编辑器（VS Code 或任何编辑器）
- 已经安装了 Git：
  - Windows: `winget install Git.Git` 或去 https://git-scm.com 下载
  - Mac: `brew install git`
  - Linux: `sudo apt install git`
- Python 3.x（用于运行演示脚本）

> ❓ **完全零基础？** 从 [s00](s00_mental_model/) 开始 — 纯概念，不敲命令，帮你建立心智模型。
> 如果你已经知道「版本控制是干嘛的」，可以直接从 s01 开始。

## 如何使用本课程

### 学习节奏

每个模块按这个顺序：

1. **读 README 的「为什么」部分** — 理解这个模块要解决什么问题
2. **读 README 的「时间树模型」部分** — 用一张图理解核心概念
3. **运行 code.py** — 在终端里看实际效果，每一步都可视化时间树
4. **自己在终端里复现** — 跟着 code.py 的输出，在自己的终端里敲同样的命令
5. **做「自己动手」练习** — 每个模块末尾有练习，一定要做
6. **再读一遍 README** — 此时有些概念你会理解得更深

### 不要跳章

每个模块的概念都依赖前一个模块。跳着学 = 浪费时间。

### 每个 code.py 做了什么？

每个 `code.py` 是一个**自动化演示脚本**：

1. 创建一个临时目录
2. 在里面执行一系列 git 命令
3. **每一步都打印时间树的可视化状态**
4. 用彩色输出区分命令、解释、结果
5. 演示结束后询问你是否保留临时仓库以便自己探索

```bash
# 运行某个章节的演示
python s23_git/s01_first_commit/code.py
```

### 遇到不懂的先记下来

有些概念（比如「暂存区」、「detached HEAD」）第一次听到不懂很正常。先记下来，继续往后学，回头再看往往豁然开朗。
