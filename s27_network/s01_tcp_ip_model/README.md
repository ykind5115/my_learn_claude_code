## 原理：快递公司的四层架构

```
┌──────────────────────────────┐
│  应用层 (Application)         │  HTTP, DNS, WebSocket, SSH
│  "信封里的内容格式"            │  → Agent 说 JSON, 浏览器说 HTML
├──────────────────────────────┤
│  传输层 (Transport)           │  TCP, UDP
│  "挂号信还是平信？"            │  → TCP 保证送到, UDP 尽力而为
├──────────────────────────────┤
│  网络层 (Internet)            │  IP, ICMP
│  "收件地址和路线"              │  → 192.168.1.1 → 1.2.3.4
├──────────────────────────────┤
│  链路层 (Link)                │  Ethernet, WiFi
│  "物理传输：网线/无线信号"     │  → 网卡 MAC 地址
└──────────────────────────────┘
```

### 封装过程：套娃

```
你的 HTTP 请求:  "POST /v1/messages..."
    │
    ▼ 应用层包裹
  [HTTP Header] + 数据
    │
    ▼ 传输层包裹 (TCP)
  [TCP Header: 端口80, 序号42] + [HTTP数据]
    │
    ▼ 网络层包裹 (IP)
  [IP Header: 源1.1.1.1, 目的2.2.2.2] + [TCP+HTTP数据]
    │
    ▼ 链路层包裹 (Ethernet)
  [MAC Header] + [IP+TCP+HTTP数据] + [CRC校验]
    │
    ▼ 物理发送 → 路由器转发 → 服务器逐层拆包
```

每经过一个路由器，IP 包被拆开看地址，重新打包转发，直到到达目的地。

## 小结

```
应用层: HTTP/DNS/TLS — "信封里写什么"
传输层: TCP/UDP     — "挂号信还是平信"
网络层: IP          — "寄到哪个地址"
链路层: Ethernet    — "网线怎么传"
```
