## 问题 — 你的 API Key 在网络上明文传输？那谁都能偷！

`sk-ant-api03-xxxxxxxx` 如果明文在 HTTP 里传输，中间任何一个路由器都能看到它。HTTPS = HTTP + TLS，把整个 HTTP 消息加密，中间人只能看到你在和 `api.anthropic.com` 通信，但看不到内容。

## 原理：加密信封

### TLS 握手（简化）

```
客户端                                     服务器
  │                                           │
  │── ClientHello ──────────────────────────→ │ "我支持 TLS 1.3, AES, RSA..."
  │                                           │
  │←── ServerHello + 证书 ──────────────────  │ "我用 TLS 1.3, 这是我的证书"
  │                                           │
  │  验证证书: 这个证书是 CA 签发的吗?           │
  │  域名匹配吗? 过期了吗?                       │
  │                                           │
  │── 用服务器公钥加密"会话密钥" ────────────→  │
  │                                           │
  │←── 切换加密 ───────────────────────────── │ "之后都用会话密钥(对称加密)"
  │                                           │
  │══ 加密通道建立 ═══════════════════════════ │
```

- **非对称加密**（公钥/私钥）：握手时用，建立信任
- **对称加密**（会话密钥）：传输数据时用，快而且安全

## 核心概念

### 证书链

```
根 CA (操作系统信任的)
  └→ 中间 CA
      └→ api.anthropic.com 的证书
```

浏览器/Python 验证证书时沿着链往上查，直到找到信任的根。

### Python 验证证书

```python
import ssl
ctx = ssl.create_default_context()  # 自动验证证书
```

## 小结

```
HTTPS = HTTP + TLS
TLS 握手 → 验证证书 → 加密通道
非对称加密(握手) + 对称加密(传输)
Agent API Key 靠 TLS 保护
```
